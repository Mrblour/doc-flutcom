Why Flutcom?

Flutcom is a lightweight Vanilla JS micro-framework that runs entirely inside the browser. It delivers the features expected from modern SPA frameworks — declarative routing, modular components, reactive state management, and lifecycle hooks — without the weight of heavy runtimes, node dependencies, or complex build tooling.

We designed Flutcom to restore the simplicity of the early web while offering the developer experience of modern frontend engineering. Write plain HTML, CSS, and ES Modules; Flutcom handles the rest with instantaneous page transitions and zero hydration delay.

High-Performance Static Sites

Deliver instant, smooth page transitions without server round-trips. Perfect for marketing, documentation, and product showcase sites.

Internal Tools & Dashboards

Build reactive admin panels and analytics dashboards using the built-in Global Store and reactive directives without build friction.

Zero Hydration Delay

The DOM is interactive on the very first byte. No multi-megabyte JavaScript reconciliation or virtual tree comparison phases.

Supply-Chain Security

Zero external runtime npm packages means zero risk from malicious downstream updates or security advisories.

v1.4.1 Security & Performance Patch

Key architectural safeguards and engine optimizations introduced in the latest release.

Patch Notes

1. Content Security Policy (CSP)

Injected into index.html to restrict script origins to origin-only, blocking external script injection vectors while allowing safe inline JSON-LD structured data. 

<meta http-equiv="Content-Security-Policy" content="default-src 'self'; script-src 'self' 'unsafe-inline'; ...">

2. Frozen Public API (Object.freeze)

The global window.Flut interface is sealed with Object.freeze(Flut), preventing untrusted scripts or third-party widgets from monkey-patching or overriding core router functions.

3. fc-click Strict Mode

Opt-in security flag site.strictMode: true in flutcom.config.js. When active, only direct Flut.method(...) calls are evaluated, rejecting arbitrary expressions. 

export const site = { nombre: "Flutcom", strictMode: true };

4. Engine Performance Optimizations

  • Static HTML Escape: Precomputed regex and escape map once at module initialization.
  • Store Equality Guard: Skips re-renders when primitive values do not change.
  • Parallel Plugin Boot: Loads plugins concurrently via Promise.all() (~3× faster boot).
  • DOM Element Caching: Pre-cached progress bar element and precomputed version query strings.

Configuration

The central source of truth for routing, metadata, and runtime options.

flutcom.config.js ES Module 
// Site metadata & runtime security flags
export const site = {
  nombre: "Flutcom",
  version: "1.4.1",
  defaultView: "home",
  notFoundView: "resources/views/public/404.html",
  strictMode: true // v1.4.1 Strict CSP & fc-click enforcement
};

// Persistent shell layout containers
export const partials = {
  navbar: "resources/partials/header.html",
  footer: "resources/partials/footer.html"
};

// Public routes dictionary
export const routes = {
  home: { view: "resources/views/public/home.html", title: "Home" },
  about: { view: "resources/views/public/about.html", title: "About" },
  docs: { view: "resources/views/public/docs.html", title: "Documentation" }
};

Routing & Guards

Navigation relies on the native hash flow (#home). Protect sensitive views with synchronous or asynchronous guards.

flutcom/main.js — Route Guards 
import { Flutcom } from './core.js';
import { routes, partials } from '../flutcom.config.js';

const app = new Flutcom({ routes, partials });

// Enforce authentication before loading the admin view
app.guard('dashboard', () => {
  const token = sessionStorage.getItem('auth_token');
  return Boolean(token); // False redirects immediately to login
}, 'login');

app.init();

View Architecture

Views are clean HTML fragments mounted directly into <flut-main>.

View Authoring Rules:

  • Do not include <html>, <head>, or <body> tags.
  • Start directly with semantic containers like <main>, <article>, or <section>.
  • Inline <script> tags are safely extracted and executed by _executeScripts() on each mount.

Reactive Directives

Built-in HTML attributes that bind DOM elements to store values without writing custom listeners.

fc-bind="key"

One-way binding. Injects store value into element textContent and updates reactively.

<span fc-bind="cart_total"></span>
fc-model="key"

Two-way data binding for input, textarea, select, and checkbox elements.

<input type="text" fc-model="user_name" />
fc-show="key"

Toggles display:none based on truthiness of store value (supports ! for negation).

<div fc-show="is_logged_in">Welcome!</div>
fc-go="route"

Navigates to route on click without writing JavaScript event handlers.

<button fc-go="about">About</button>

Global State Store

Reactive state container with equality guards to skip redundant renders.

JavaScript Store Interaction 
import { Flut } from './flutcom/flut.js';

// 1. Set values in the global store
Flut.set('user_theme', 'dark');

// 2. Read values
const theme = Flut.get('user_theme');

// 3. Subscribe to reactive changes
Flut.subscribe((key, val) => {
  if (key === 'user_theme') {
    document.documentElement.className = val;
  }
});

Plugins Architecture

Modular extension engine featuring non-blocking parallel initialization and memory leak protection.

v1.4.1 Engine

Flutcom plugins are self-contained ES modules that hook into the application lifecycle without altering framework core files. In v1.4.1, plugin initialization was overhauled from sequential iteration to concurrent execution via Promise.all(), achieving ~3× faster application bootstrap.

Parallel Bootstrapping

All registered plugins load simultaneously using Promise.all(). If one plugin throws, others continue uninterrupted.

Lifecycle Hooks

Exposes init(app, cfg) for setup and onNavigate(view, container) to refresh DOM interactions per route.

Memory Leak Safeguards

animations disconnects and unobserves DOM nodes on route transitions, preventing retain cycles.

Plugin Dual-File Architecture

Every native plugin resides in its own folder inside plugins/<name>/ with two companion files:

1. Manifest (.json) plugins/<name>/<name>.flutcom.json

Defines metadata, version, and the enabled: true/false toggle.

2. Implementation (.js) plugins/<name>/<name>.flutcom.js

Exports an object implementing init() and onNavigate().

plugins/telemetry/telemetry.flutcom.js Custom Plugin Example 
export default {
  name: 'telemetry',
  version: '1.0.0',

  // Called once when Flutcom boots (in parallel with other plugins)
  init(app, config) {
    this.app = app;
    this.startTime = Date.now();
    console.info('[Telemetry] Initialized');
  },

  // Called on every client route transition
  onNavigate(viewName, container) {
    const renderTime = Date.now() - this.startTime;
    console.info(`[Telemetry] View switched to #${viewName} in ${renderTime}ms`);
  }
};
flutcom.config.js Plugin Registration 
// Register plugins to boot simultaneously in parallel
export const plugins = [
  "timer",       // Boot time and runtime benchmark
  "menu",        // Accessible navigation and mobile drawer
  "animations",  // Reveal animations with auto unobserve/disconnect (v1.4.1)
  "responsive",  // Reactive viewport breakpoint detection
  "motion",      // Page-to-page transition smoothing
];
